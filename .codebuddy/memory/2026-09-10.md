## 第十三批（弹窗 header 底边线右侧缩短——用户报告修复）
- **用户现象**：弹窗 header 底边（border-bottom）最右侧和右边缘有一段距离、左侧却贴边，"像 header 被左移"。用户澄清是**弹窗** header（先误诊为 shell header，已回滚该改动恢复 `margin-right:88px`）。
- **根因**：`.modal-card` 等 7 个卡片规则带 `scrollbar-gutter:stable`；`.settings-modal`/`.management-dialog` 是 `padding:0 + overflow:hidden`（自身永不滚动，内部 body 才滚动）——overflow:hidden 也是 scroll container，gutter 照样预留 8px（项目自定义 `::-webkit-scrollbar` 宽 8px）**死槽**；通栏 sticky header（settings-heading/management-heading，无负 margin、靠卡片 padding:0 贴边）画不进 gutter → 底边线右端短 8px。实测 gapLeft=1 / gapRight=9。
- **修复**：删除全部 7 处 `scrollbar-gutter:stable`（modal-card、translation-terms-card、update-prompt-card、sending-status-details-modal、accounts-editor-modal、contact-editor-modal、calendar-editor-modal）。弹窗内长列表本就是独立滚动容器（auto-reply-list、agent-memory-list 等），卡片级预留零收益。修复后 gapLeft=1 / gapRight=1。
- **教训**：`scrollbar-gutter:stable` 对 overflow:hidden 的盒子**同样生效**（hidden 也是 scroll container）；通栏 header + 卡片级 gutter 预留是互斥模式。
- 顺带发现（未改，待用户定夺）：`.desktop-app .column-header { margin-right:88px }` 使 header 盒子比下方内容（list-toolbar/滚动条伸到 rail）右端短 88px，可改 `padding-right:106px`（内容位置不变、盒子对齐 rail 分隔线）——已验证可行后回滚。
