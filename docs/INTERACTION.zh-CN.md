# NamiMail 交互约定

[English](INTERACTION.en.md)

本文记录跨模块复用的交互规则。它们来自已修复的真实缺陷：**每一条都对应一个曾经出现过的状态错乱或输入丢失**，新增交互时请照此实现，而不是照隔壁模块的实现猜。

## 1. 批量操作完成后必须退出多选态

- 多选操作**成功** → 清空选择并退出多选态；**失败** → 保留选择，便于重试。
- 理由：处理完的选中项若继续保持选中，用户下一次点击任意一行就会再触发一次批量操作。
- 实现位置：`App.tsx` 的 `batchUpdateFlags`（`applied` 标志控制 `exitSelectionMode()`）、谓词批量任务路径的 `exitOnSuccess`。
- 部分失败时，失败行要在「对账 reload」**之前**解除乐观 pin，否则它的乐观值会压过服务端真相。

## 2. 乐观更新：先本地生效，失败必须回滚

凡用户可感知的操作都先本地生效。已经乐观化的：发送、新建会话、删除、撤回消息、重命名、记忆建议、确认卡审批、标记已读/加星/移动。

刻意**不做**乐观的（服务端确认才是有意义的语义）：自动回复审批。

回滚要求：失败必须还原到操作前的状态，不允许出现「界面一个值、服务端另一个值」。

## 3. 取消/停止类操作必须即时反馈

停止生成、关闭窗口、取消请求这类操作，本地要**立刻**收起相应状态（按钮、spinner、进度），不能等服务端回包往返结束才变。

## 4. 服务端快照不得整体替换本地已更新的状态

刷新、轮询、切回会话取到的服务端快照可能早于本地已发生的变化。合并规则：

- 流式正文：run 仍在跑时保留更完整的一份（`keepAheadTranscript`），run 结束后服务端为准；
- 邮件行：只覆盖受保护（pin）之外的字段，pin 用**计数**而非 Set（同一行的两个并发操作不能互相撤销保护）；
- 计数与徽标：与行同源修正（`applyPinnedUnseenCorrections`），否则徽标会跳回旧值；
- 未读视图总数：取服务端数，保留的已读行由文案单独报，不能重复计入。

## 5. 后台刷新不得覆盖正在编辑的内容

任何列表刷新、轮询、保存回包，都不得清掉用户正在填写的表单（尤其 API Key）。规则：编辑即置脏；只有显式切换条目、保存成功、删除才允许重建表单。

## 6. 取数必须有纪元，输入要有防抖

- 每个列表/详情取数都要有请求纪元（requestId），只有最新一次可以写状态；
- 搜索类输入必须防抖后再发请求；
- 「有请求在飞就丢弃」不是保护——调用方（如审批后的刷新）需要它执行，应改为排队重跑。

## 7. 退出与销毁不留残留

关闭、更新安装、启动失败三条路径都要清理子进程与订阅；订阅不要因为回调身份变化而反复拆装（窗口期内到达的事件会无人接收）。
