# 官网与交互演示

官网由 `site/` 静态页面和复用 `apps/web/` 构建的交互演示组成。演示使用示例账户与邮件数据；邮件助理显示预设会话、回答和来源引用，不连接真实邮箱，也不需要模型服务。独立演示入口默认进入 `demo=1&preview=site`，页面带有 `noindex,nofollow`，并以 CSP 的 `connect-src 'none'` 禁止网络连接。

## 本地构建和预览

在仓库根目录安装依赖后，运行：

```powershell
node scripts/build-site.mjs
node scripts/preview-site.mjs
```

构建器从 `docs/` 生成文档页和 sitemap，编译共享的 Agent contracts，再将 `apps/web/` 输出到 `site/demo/`。预览服务默认监听 `127.0.0.1:5176`。

官网演示分别固定在收件箱和邮件助理视图；邮件来源在浮层内阅读，不会切换工作区。此限制只作用于 `preview=site`，普通客户端与开发用 `demo=1` 保留工作区切换。

演示主体至少四分之一进入视口、滚动停稳后才自动加载客户端，首屏绘制前就保留高度以避免页面或锚点跳动。未加载和加载中显示与客户端相同的 Logo、字标展开和加载条，不显示手动启动按钮。客户端就绪后，启动占位淡出，真实界面淡入并轻微上移；开启减少动态效果时直接切换。只有加载失败时才显示重试按钮，不支持 IntersectionObserver 时也会通过可见区域检测自动启动。滚出视口不会丢失已载入的演示状态，打开和关闭来源浮层也不会改变官网滚动位置。

官网的主题和语言控制只重新加载已经启动的演示，尚未启动的演示会在进入视口时使用最新选择。演示中的重置按钮会恢复初始数据。网站演示延后显示首次翻译提示，不会记录用户已同意条款；主动使用翻译时仍需确认。

客户端就绪且演示主体至少一半可见时，会自动播放一轮三步演示：收件箱依次展示统一收件箱、按发件人搜索和阅读正文；邮件助理依次展示回答、展开引用和阅读原邮件。操作步骤停留约两秒，阅读步骤保留约三秒，关键区域平滑放大。模拟鼠标先移动到操作位置再点击，位置随画面缩放；不添加 focus 框。特写只变换真实客户端画面，不另建展示界面；`site/demo-tour.js` 调用同源 iframe 中已有的搜索、阅读和来源按钮，不请求模型或邮箱 API。

滚出视口或切换浏览器标签页会暂停，返回后继续。用户在客户端内点击、输入或滚动会接管演示，画面恢复原比例；只有主动点击播放才会再次演示。工具栏提供暂停、重播和特写开关，一轮结束后保留手动体验。窄于 760px 的演示不放大；开启减少动态效果时默认不自动播放，用户仍可主动播放无特写的步骤。官网预览不在空闲时预加载各类弹窗，手动打开时再加载；普通客户端的预加载策略保持原状。

标签页图标统一使用应用品牌轮廓。README 顶部使用透明背景的 SVG 字标，由 `wordmark-reference.png` 与同一品牌轮廓生成；文字颜色会根据 `prefers-color-scheme` 自动适配。`npm run build:brand` 生成品牌 SVG，`npm run build:brand:check` 验证生成结果是否同步。

官网、文档总览和文档正文使用同一组顶部入口：首页、功能、邮件助理、本地与隐私、文档和 GitHub；
下载按钮的位置也保持一致。当前页或首页章节用 `aria-current` 标出，文档目录与页内目录保留在文档区域。
900px 及以下使用相同的手机菜单；关闭 JavaScript 后菜单和跨页链接仍可用。导航样式统一放在 `site/base.css`，
文档页默认主题与官网一致，往返时保留语言和主题选择。

## 官网交互回归

构建完成后，可运行独立的 Playwright 站点测试：

```powershell
npx playwright test --config playwright.site.config.ts
```

测试覆盖首页两个 demo、邮件搜索与标星、网站主题和语言同步、助理来源引用、窄屏菜单、独立 demo 的安全默认参数，以及 demo 不发起 API 请求。
还验证视口外显示启动动画且不请求客户端、无手动启动按钮、就绪时保留高度和滚动位置、工作区固定、来源浮层的焦点恢复、加载失败后重试和不支持 IntersectionObserver 时自动加载。
导航回归还覆盖官网与文档往返、顶部入口及位置稳定、中英文文档切换、390px / 850px 菜单和无 JavaScript 导航。
自动演示回归覆盖真实搜索与阅读、来源浮层、一轮结束、特写切换、用户输入接管、离屏暂停与恢复，以及减少动态效果和窄屏布局。

## 发布

GitHub Pages workflow 在相关页面、文档、Web 客户端、contracts 或构建配置进入 `main` 后构建并发布 `site/`；也可手动触发 workflow。`site/demo/` 是构建产物，不提交到仓库。客户端源码、文档页和 sitemap 在同一次发布中生成。

PR 校验会在 Ubuntu 上执行与 Pages 相同的 `npm ci --ignore-scripts` 和 `node scripts/build-site.mjs`；必需的 `validate` 检查也要求这项 Linux 构建通过。脚本测试会检查锁文件是否包含 Rolldown、Lightning CSS、esbuild 和各工作区 TypeScript 声明的全部平台原生包。修补锁文件时，应按现有工具版本在没有 `node_modules` 的干净暂存目录中解析原生依赖，并在提交前核对依赖版本。
