# RAG 清洗

[简体中文](cleaning.zh-CN.md) | [English](cleaning.en.md)

## 原则

清洗只生成检索副本，不修改原始加密邮件、渲染 HTML 或执行其中的资源。优先使用有意义的 `textBody`；只有没有纯文本时才把受限 HTML 转为文本。清洗结果记录版本、来源、是否截断、是否移除了引用和签名，以及内容 hash。

## 当前清洗管线

1. 规范化换行、Unicode NFC 和控制字符。
2. 对 HTML 删除脚本、样式、表单、iframe、嵌入对象、SVG、图片、隐藏节点、注释和标签，保留可读块/表格/列表文本。
3. 解码受限 HTML entity，清理常见跟踪参数。
4. 去除引用边界、`>` 引文、明显签名和中英文保密声明。
5. 规范化空白、相邻重复段落，并在字符预算处尽量按自然边界截断。
6. 对最终文本计算内容 hash，而非把原始 HTML 或外链当作语义内容。

清洗器不保证完美删除所有免责声明或所有注入文本。它的安全作用是缩小/标准化上下文；模型仍必须把结果视为不可信邮件数据。

## 版本和变更

`MAIL_CLEANER_VERSION` 是 RAG 页面可复现性的组成部分。改变规则、最大长度或解析行为时，需提升版本、创建受控回填并保留新旧结果的可比测试。不要在运行中静默用新规则覆写旧页面而不更新修订/摘要。

## 测试边界

至少覆盖纯文本优先、恶意 HTML、隐藏文本、CJK、长内容、引用、签名、跟踪 URL、无效 Unicode 和空正文。测试不得将真实邮件、凭据或附件放入固定夹具。
