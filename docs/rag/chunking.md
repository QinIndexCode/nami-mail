# RAG 分块

[简体中文](chunking.md) | [English](chunking.en.md)

## 目标

分块将清洗后的邮件变成稳定、可引用、受预算约束的检索页面。它不是按任意字符切割，也不借助远端 tokenizer 才能重现；当前页面由词法检索使用，不表示已提供语义 embedding。

## 当前规则

- 先识别主题、段落、列表、表格和混合块。
- 以 CJK 字符、词语和标点构成的本地估算控制目标/最大 token 预算。
- 优先在段落和句子边界组合块；超长块按句子或安全字符边界拆分。
- 每块包含确定性 `chunkId`、索引、类型、文本、token 估算、内容 hash 和 `MAIL_CHUNKER_VERSION`。
- `messageId`、来源修订、主题和清洗文本共同决定页面身份；同样输入必须给出同样顺序和 hash。

当前默认目标约为 360 token、最大约为 520 token。这是本地预算，不是某一模型的精确 token 计数；Provider 有不同限制时由 Runtime 再裁剪上下文。

## 主题和引用

主题可以作为独立小块或与第一内容块关联，以提升查询可解释性。每个块必须能映射回消息、修订和块索引，引用展示时应给出必要片段而不是由模型自由编造来源。

## 版本迁移

改变识别规则、预算或 ID 生成即改变索引语义。提升 `MAIL_CHUNKER_VERSION` 后，应新建修订、受控回填并在一致性检查中淘汰旧活动页；不要就地替换仍被会话引用的旧密文记录。

## 不做的事

不基于用户语言自动翻译文本再分块；实验性 NLLB 翻译保持独立、主动触发，不能成为 RAG 摄取的隐式步骤。

参见 [检索](retrieval.md) 和 [摄取](ingestion.md)。
