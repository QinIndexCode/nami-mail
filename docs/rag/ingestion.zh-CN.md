# RAG 摄取

[简体中文](ingestion.zh-CN.md) | [English](ingestion.en.md)

## 来源事件

RAG 不轮询猜测邮件变化。既有同步或邮件操作在其本地 SQLite 事务内提交邮件变化，同时入队 Agent 来源事件。当前邮件状态接线会写入消息 upsert/delete 与账号 generation/删除事件；附件事件类型是为后续解析器保留的契约，当前生产者不会单独创建附件文本来源事件。

事件包含事件 ID、账号、generation、来源修订、发生时间、类型和摘要。敏感来源定位符以加密方式保存；公开的存储视图只暴露不透明摘要，避免后台队列泄露消息 ID 或正文。

## 原子性与重试

- `enqueueWithinTransaction` 必须由已经打开的同一数据库事务调用；邮件写入回滚时事件也回滚。
- 这不宣称与 IMAP 或 SMTP 的全局分布式事务。远端不确定状态仍由既有同步/发件核对解决。
- 工作者只 claim `pending`/可重试失败事件，处理完成后标记 `completed`；可恢复故障记录错误码和下次尝试。
- 同一来源、修订和事件类型去重。重复投递必须幂等，不能创建重复页面或重复引用。

## 摄取步骤

1. 验证事件账户与当前 generation，注册可取消任务。
2. 从受限的既有邮件服务读取当前来源，而不是相信事件正文。
3. 清洗出检索副本，按确定性规则分块，计算版本和内容摘要。
4. 在同一 generation 写入加密页面并更新内存检索结构。
5. 再次检查任务仍为当前代际，完成事件；过期任务必须取消而非提交。

当前 RAG 不从附件正文创建页面。附件元数据变化只会让工作者重新处理父邮件；二进制、加密、损坏、超大或解析失败的附件不会被解析、上传或作为可检索正文。未来附件解析器必须先有独立的授权、大小/类型限制、可解释失败状态和测试，且不能阻塞整个账号或偷偷外发内容。

## 回填与重建

首次启用、清洗/分块版本变化或索引损坏可创建受限回填任务。回填必须有账号范围、速率/内存预算、可取消性和可观察进度；它不能越过删除 generation，也不能覆盖正在提交的较新修订。重建只重建 Agent 页面和内存结构，不迁移或改写原始邮件。

参见 [清洗](cleaning.zh-CN.md)、[分块](chunking.zh-CN.md) 和 [删除同步](deletion-sync.zh-CN.md)。
