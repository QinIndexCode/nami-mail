# RAG 删除同步

[简体中文](deletion-sync.zh-CN.md) | [English](deletion-sync.en.md)

## 消息删除和附件元数据变化

本地邮件状态删除、草稿删除或远端同步确认删除时，在同一 SQLite 事务中写入删除来源事件。工作者根据来源 ID/修订使对应页面失活或删除内存候选；重复删除必须安全且幂等。检索查询永远过滤 `deleted` 页面，而不是依赖异步清理完成才隐藏结果。

当前运行时不维护附件正文页面。附件元数据变化会重新处理父消息，消息删除才会使父消息的 RAG 页面失活；不要把保留的附件事件契约描述成已交付的附件索引或删除流程。

移动、归档和 UID 变化不是简单删除：应复用既有邮件同步语义，按实际本地来源修订产生 upsert/delete 事件。尤其在 IMAP 不确定结果时，不能因为 Agent 索引需要“整洁”而把邮件或页面错误地宣称已删除。

## 账户删除围栏

账户删除流程按如下顺序：

1. 在受控事务中将账号推进到新的 `generation`，状态置为 deleting，并丢弃旧 DEK 包装。
2. 取消旧 generation 的来源事件和正在运行的索引/查询任务。
3. 写入账号 generation/删除事件，供内存结构淘汰和维护记录使用。
4. 执行既有邮件账户删除；成功后标记 Agent 生命周期 deleted。
5. 若邮件删除被取消或失败，创建该 deletion generation 的新 DEK 并重建 Agent 数据，绝不恢复旧 DEK。

这不是对物理行立刻擦除的承诺：DEK 被丢弃后旧密文已不可读取。物理 purge 可在明确的维护流程中进行，且不能越过仍需审计的记录或破坏迁移证据。

## 代际检查

所有页面写入、事件 claim/完成、会话读取、确认消费和检索都必须比较 account ID 与 generation。旧任务在最后提交前再检查；若不匹配，取消并留下可解释的 `account_generation_revoked`/`stale_account_generation` 状态。

## 验收场景

- 删除一封邮件后，查询立即不再返回该页面，即使异步物理清理未发生。
- 删除账户后，旧页面/会话密文无法被现有主密钥解封。
- 账户删除失败时，不会悄悄恢复旧数据密钥；只能从仍存在的邮件源重建。
- 重复/乱序删除事件不能让新修订页面消失。
