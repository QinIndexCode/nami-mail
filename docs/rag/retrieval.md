# RAG 检索

[简体中文](retrieval.md) | [English](retrieval.en.md)

## 查询边界

检索请求必须先有已验证的 caller、账户范围和当前账号 generation。先应用权限和 scope，再查询页面；不能先在全库召回、再在 UI 中过滤。已删除、旧 generation、内容摘要不匹配或无法解密的页面不会成为候选。

## 当前检索

当前运行时仅使用词法词项评分和结构化范围过滤。它会先验证账号范围、当前 generation、消息限制和页面状态，再从内存中的已解密活动页计算分数并复核引用。持久页保持加密，词法内存索引可从页面和来源事件重建；当前没有已接线的生产 embedding Provider、语义索引或向量数据库。

推荐流程：

1. 规范化查询并限制长度、账户、时间/文件夹等过滤器和结果数量。
2. 读取当前 generation 的活动页面，计算词法候选并按分数排序。
3. 按来源/修订复核候选，并施加结果与页面上限。
4. 验证页面仍可解密且来源仍属于当前范围。
5. 输出带稳定分数解释和引用的结果；Provider 只得到被选择的最小上下文。

## 来源引用

每项结果应包含账号、消息或页面标识、来源修订、块索引、必要片段和应用内跳转信息。引用不是模型回答的“可信证明”：UI 应允许用户打开原邮件、选择/复制文本，并明确指示索引可能过时或清洗过。

## 未来 Embedding 边界

Embedding 是预留的可替换边界，不是当前运行时能力。未来若接入云 embedding，邮件文本外发必须由单独、可见的用户同意控制，并显示 Provider 与范围；在实现、审查和验证前，不能把语义结果或云 embedding 写成已可用功能。

## 性能和降级

查询需要有时间、内存和候选数量预算。内存索引缺失、Provider 不可用、页面暂未就绪或账户正在删除时，应返回可解释状态而非部分越权结果。不得通过持久化明文缓存来改善冷启动。

参见 [一致性](consistency.md) 和 [安全](../agent/security.md)。
