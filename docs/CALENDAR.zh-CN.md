# 日历与邮件邀请
<!-- shipped-as: v0.6.0 -->

[简体中文](CALENDAR.zh-CN.md) | [English](CALENDAR.en.md)

Nami Mail 内置一个本机日历：月视图浏览、事件创建、编辑、删除、搜索与 ICS 导入/导出。日历数据只保存在本机数据库中，不与服务商日历（如 Google 日历、CalDAV）互同步。

## 邮件邀请横幅

阅读带有 `.ics` 附件的邮件时，阅读区顶部会显示日历邀请横幅，展示首个事件的主题、时间与地点，并识别常见线上会议链接（腾讯会议、Zoom、飞书、钉钉、Microsoft Teams、Google Meet），点击即可直达入会。

横幅提供两个操作：**导入到日历**（把附件内容送入导入弹窗）与**查看日历**。为避免重复下载，附件解析结果会按"邮件 + 附件"缓存，重访同一封邮件不再重新下载；超过 10MB 的附件会在下载前直接拒绝并提示。

## ICS 导入

导入弹窗支持选择本地 `.ics` 文件（或从邀请横幅带入附件内容）。导入前会先本地解析并预览事件数量，解析失败会明确提示。

- **大小限制**：文件超过 10MB 会在读取前被拒绝；解析器另有 5 万行上限，防御解压炸弹。
- **追加模式（append，默认）**：把事件加入现有日历。事件按 ICS 的 UID 去重——重复导入同一份日历不会产生重复日程，而是原地更新既有事件（结果计为"已更新"）。
- **替换模式（replace）**：清空现有全部日程后导入本次内容。

导入事件保留原始 UID；本机创建事件使用稳定的内部 ID 作为 UID，旧版 UID 为空的日程也按该 ID 匹配。因此本机日程的“导出 → 追加导入”会更新原行，不再创建重复日程。

合法的 `TZID` 按 IANA 时区和夏令时转换；没有时区的浮动时间按本机时间解释。无效日期、未知时区和不存在的夏令时时刻会明确报错，不会替换成当前时间，替换导入前也会先完成解析。周期规则（RRULE）、例外实例和取消邀请的完整语义目前仍不受支持。

界面会跟随日历接口游标取完事件，提醒则按近期时间窗口独立查询，不再被最早 1000 条历史日程挤出。

## 事件提醒

应用运行期间会在普通事件开始前 15 分钟弹出应用内提醒（toast）；全天事件则固定在当日早晨 09:00 弹出提醒。点击通知均可直达日历对应视图。已提醒过的同一事件不会重复提醒；超过开始时间 30 分钟的过期提醒会被忽略。提醒遵循系统通知开关——关闭新邮件通知后日历提醒同样静默。提醒去重记录保存在本机浏览器存储中（最多 200 条）。

## Agent 日历工具联动

内置 Agent 注册了 `calendar.list`、`calendar.create`、`calendar.update`、`calendar.delete`。写操作遵循 Agent 权限档位：默认 send-confirmed 需可见确认，full-access 按启用时的授权执行。日历服务不自动进行云同步；启用云端 Agent 时，选取的日程可作为对话上下文发送给已获授权的 Provider。

## 本地存储与边界

- 事件主题、描述、地点使用主密钥派生密钥进行 AES-256-GCM 加密；时间以 UTC 字段查询。自 0.6.0 起数据库文件还受整库加密保护，不能把解锁后的字段表示误认为磁盘上的明文。
- 事件的字段长度有限制：主题 300 字符、描述 10000 字符、地点 500 字符；单次导入最多 5000 个事件。
- ICS 解析在本机完成，邀请横幅通过本机服务读取附件；日历服务不自动向第三方同步。云端 Agent 的上下文外发另受 Provider 授权约束。
