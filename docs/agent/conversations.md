# Agent 会话

[简体中文](conversations.md) | [English](conversations.en.md)

## 数据模型

会话元数据和范围保存在 `agent_conversations` 与 `agent_conversation_scopes`；消息、工具记录和必要的上下文记录保存在按账户/代际加密的 `agent_conversation_records`。记录以追加方式保存，数据库触发器禁止更新和删除已写入的记录。

会话本身只管理本地上下文，不改变原始邮件、草稿或发送队列。删除会话是逻辑删除；它不等于清除邮件，也不得作为账号删除密钥围栏的替代手段。

## 范围和上下文

创建会话时，用户选择一个或多个账户范围。每条记录都绑定账户 ID 与当前 generation，读取时需要再次验证其生命周期仍可用。跨账户总结只能使用用户明确选择的账户；来源引用也保留该范围。

上下文构建遵循最小化原则：优先使用用户选中的消息、已授权的 RAG 页和结构化元数据，按 Provider 能力和预算裁剪。邮件文本始终标注为外部数据，不能要求 Runtime 忽略安全规则、调用工具或向外发送更多内容。

## 生命周期

1. 创建会话并固定初始范围。
2. 追加用户消息、Assistant 流事件、工具结果、引用和确认状态。
3. 支持取消当前请求；取消不会删除此前已持久化记录。
4. 标记/删除会话时从普通列表隐藏，同时保留必要的审计关联。
5. 账户删除推进 generation 并丢弃该账户 DEK 后，旧会话记录应变为不可解密，不能被“恢复会话”功能重新展示。

当前源码不仅包含可测试的会话、确认和审计存储，也包含嵌入式 GUI 会话路由、流事件和确认卡片。它们仍不是已交付声明：必须在同一版本完成集成测试、打包桌面 smoke、真实 Provider/账户路径以及删除与恢复边界验证。

## 用户体验要求

- 流式回答、来源和错误必须可选择和复制。
- 来源可以打开相应邮件，但不改变其已读状态，除非用户执行已有邮件界面的显式操作。
- 停止、重试、删除和确认必须显示实际状态，不能把 Provider 超时伪装为已完成。
- 无 Provider、未同意外发或索引未就绪时保留输入和会话，提供明确下一步。

## 保留与清理

不会为了节省空间悄悄截断审计或未确认操作。物理清理必须是显式维护任务，并验证不会破坏未删除账号的会话、确认或审计关联。账号 DEK 已移除时，密文不可恢复；不要尝试从备份重新写回旧 DEK 以“修复”会话。

参见 [RAG 删除同步](../rag/deletion-sync.md) 和 [安全](security.md)。
