# 决策记录

[English](README.en.md)

这里保存**已经生效的结构性取舍**：它在什么情况下被做出、当时看到了什么证据、选了哪条路、放弃了什么。

- 它**不是**路线图：不承诺时间表，也不写"将来会做"。
- 它**不是**缺陷列表：能力边界与刻意不做的取舍记在[已知限制](../known-limitations.zh-CN.md)。
- 它**不随实现更新**：实现现状以[架构文档](../../ARCHITECTURE.zh-CN.md)与代码为准。决策被推翻时，写一份新记录并把旧的标为 `已替代`，不要原地改写历史。

## 什么时候需要写

同时满足以下两条时才写：

1. 改动跨模块或不可逆——替换一层持久化、改动 HTTP 契约、并入或删除既有模块、改变加密或数据模型。
2. 半年后有人会问"当初为什么这么选"，而答案不写在代码注释里也能成立。

不需要写的：单个接口的形状调整、界面交互细节、一次性的修 bug。这些留在提交说明与代码注释中。

## 怎么写

- 一个决策一份文件，命名 `NNNN-YYYY-MM-topic.zh-CN.md` / `.en.md`，编号连续。
- 小节顺序固定：**状态与范围 → 背景（问题是什么症状、为什么不是三个 bug）→ 决策（表格：决策 / 为什么 / 放弃了什么）→ 后果（得到什么、付出什么、怎么验证）→ 不属于本决策 → 依据**。
- 决策条目用稳定编号（`D1`、`D2` …），后续记录引用编号而不是引用段落。
- 每条决策必须写出**放弃了什么**。只写收益的决策记录没有价值。
- 数字要给来源与测量条件；无法核实的写"未核实"，不要估算。
- 两版语言结构一一对应；英文是中文的译文，不改写结构。

## 状态词

| 状态 | 含义 |
|---|---|
| 提议 | 已写出、尚未生效；可以继续修改 |
| 已采纳 | 代码已按它落地；修改它需要一份新记录 |
| 已替代 | 被后续记录取代，保留作为历史；在被指向的新记录里说明替代了什么 |
