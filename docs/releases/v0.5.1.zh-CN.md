# Nami Mail 0.5.1

[简体中文](v0.5.1.zh-CN.md) | [English](v0.5.1.en.md)

Nami Mail 0.5.1 是一个关键的补丁版本升级，重点修复了 Windows 平台下应用内更新时点击“重启并更新”导致应用静默退出、无法自启以及覆盖安装参数缺失的核心缺陷。

## 下载与重要升级指引

- **手动升级指引（仅限 0.4.3 与 0.5.0 用户）**：
  由于 `0.4.3` 与 `0.5.0` 客户端内部打包的旧版更新器包含后台进程启动缺陷，**已安装 `0.4.3` 或 `0.5.0` 的用户无法直接在应用内完成自动升级，请直接从本 Release 页面下载 `Nami-Mail-Setup-0.5.1.exe` 手动运行覆盖安装**。
  - 本次手动覆盖安装会**完全保留**现有的本地邮箱数据、账户配置与加密密钥，不需要重新登录或重新配置。
- **后续版本自动更新恢复**：
  安装 `0.5.1` 之后，更新器核心逻辑已完成彻底修复；后续版本（如 0.5.2、0.6.0 及以后）在应用内的自动下载和“重启并更新”将全面恢复正常，支持就地静默无缝升级。
- 请只使用匹配 GitHub Release 页面列出的 Windows `.exe` 安装程序。版本化 ZIP、JSON 更新清单、`latest.yml` 和 `.blockmap` 用于发行与应用内更新，不是手动安装包。

## 更新与签名状态

- 发布前验收：CI 全量验证通过（typecheck / lint / 单元与集成测试 / e2e / desktop smoke / 桌面安全测试）；通过 268/268 项桌面与更新安全测试。
- `0.5.1` Windows 安装程序采用 Ed25519 清单签名作为更新信任根；未进行 Authenticode 签名。Windows SmartScreen 可能显示未知发布者警告。请勿绕过 Windows 安全警告，只应从本 Release 页面获取安装程序。
- 就地升级会保留现有本地数据；不会仅因本次更新而要求重新登录或重新授权账户。

## 本次更新

- **修复 Windows 自动更新脱钩与静默退出缺陷（Node.js Issue #51018）**：
  - 彻底重构更新器后台 PowerShell 启动机制：解决原 Node.js `spawn` 传递 `detached: true` 导致 Win32 `DETACHED_PROCESS` 使 CUI 控制台初始化失败闪退的严重问题；
  - 改用 Windows 系统内置命令 `cmd.exe /d /s /c start "" powershell.exe -WindowStyle Hidden ...`，在独立且完整的会话中拉起后台更新与安装进程，不受父进程退出影响。
- **补齐 NSIS 原地覆盖升级参数**：
  - 安装器执行参数显式补齐 `@('/S', '--updated')`，严格对齐 `installer.nsh` 的静默升级逻辑，杜绝误触发运行冲突确认弹窗，并防止覆盖升级时误抹除或重置用户的自定义安装路径。
- **修正重启工作目录漂移**：
  - 更新完成自启动新版本主程序时，显式指定 `-WorkingDirectory (Split-Path -Parent $CurrentExecutablePath)`，防止因从 `cmd.exe` 启动而让新进程工作目录错误漂移为 `C:\Windows\System32`。
- **增加更新失败缓存熔断与死循环保护**：
  - 当启动检测发现记录的更新未成功改变运行版本时，主动清理损坏或未应用的更新包缓存，彻底杜绝重启后无限弹出“重启并更新”提示。

## 安全与范围

- 本地优先原则始终如一：日历、多模态解析及会话数据均完全保存在本地；
- 云端模型必须显式开启邮件内容授权后才可在授权范围内检索；
- 更新信任根保持不变：GitHub 更新资产继续使用 Ed25519 清单签名校验。

## 已知问题与限制

- **Outlook / Hotmail 账户在默认安装下暂无法直接登录（跟踪 Issue #120）**：微软已关闭密码认证强制采用 OAuth2，由于官方构建尚未内置 Azure OAuth Client ID，当前微软登录暂不可用；可在 `%APPDATA%\Nami Mail\nami-mail.env` 配置 `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` 环境变量临时使用。
- **平台支持**：当前仅提供 Windows x64 桌面版。
- **搜索与检索**：本地检索不摄取附件正文；中文按单字切分。
- **第三方服务**：云端模型与翻译服务可用性取决于所选第三方服务提供商。
