# Nami Mail 0.4.0

[简体中文](v0.4.0.zh-CN.md) | [English](v0.4.0.en.md)

Nami Mail 0.4.0 is a stability-focused update: it fixes the cascade of races behind revoke-then-resend in the Agent and the "banner pops up but no sound" problem with the new-mail notification sound, completes conversation threading and quote folding, and launches the website and documentation site.

## Download

Use only the Windows `.exe` installer listed on the matching GitHub Release page. The versioned ZIP, JSON update manifest, `latest.yml`, and `.blockmap` are for distribution and in-app updates, not manual installers.

## Update and signing status

- Pre-release acceptance: the full CI validation passed (typecheck / lint / unit and integration tests / e2e / desktop smoke / dependency audit); the release job runs a package smoke after signing and packaging and verifies the draft asset integrity before promoting the release.
- Public-network auto-update verification from `0.3.0` to `0.4.0` is still pending. This release does not claim the online upgrade path has been verified until the isolated verification is complete.
- The `0.4.0` Windows installer is not Authenticode signed. Windows SmartScreen may show an "unknown publisher" warning. Do not bypass Windows security warnings; get the installer only from this release page.
- In-place upgrades keep existing local data; no re-login or re-authorisation is required by this update alone.

## What's new

- **Agent revoke/resend race fix**: the server releases the conversation slot as soon as a turn is persisted, so the first-turn title generation tail no longer holds it (up to ~two minutes on a slow provider); the client adopts the server snapshot when a revoke hits "not found" and keeps the refilled composer text for resending. Resending right after a revoke is no longer refused, no phantom rows or duplicate messages appear, and no re-entry is needed to recover.
- **Fail-safe new-mail notification sound**: the main process plays the sound first and shows the banner afterwards; playback failures fall back to a system-sound notification and are logged to the runtime log; the pipeline is warmed up at startup, removing the ~1.5 s cold-start delay of the first notification; the Settings "test notification / test sound" buttons use the same pipeline as a real alert.
- **Conversation thread completion**: Gmail-style grouping across folders; missing members are completed through `GET /api/messages/:id/thread` (a bidirectional transitive closure over RFC headers within the account, drafts excluded, yielding the event loop between rows while decrypting); threads are refetched automatically after sending.
- **Quote auto-folding**: top-level HTML quotes collapse into native `<details>` elements and trailing `> ` blocks collapse in plain text; folding happens only at the render layer, while translation and reply-quote pipelines keep the full body.
- **Mail direction display fix**: mail the user sent themselves is rendered by recipient (reading-view avatar/main name, a To line with the recipient's avatar in the list, quick reply pre-filling the original recipient) instead of guessing the direction from the folder name.
- **List-switch flicker fix**: the list identity follows only the landed snapshot; in-flight old rows merely dim as a whole.
- **Agent web-search tool hardening**: no longer depends on the search result page's class names (whose changes used to make it return zero results forever) and parses attributes and links in two steps; search activity shows the real query and a result summary (backward compatible with old records).
- **Streamlined Settings**: removed 21 redundant subtitles and condensed 11 (both locales); the select control's font size matches its open menu; added a Settings localization interaction test.
- **Badge-style update notice**: a round badge in the lower-left corner expands into a "new version x.y.z" pill on hover and dismisses with a layered animation; the main copy changed from "local encryption" to "data stays on this device".
- **Folder icon semantics**: junk mail is now a shield with an exclamation mark and All mail is a stacked-layers icon; fixed vertical alignment.
- **Website and documentation site**: a landing page plus docs pages deployed automatically to GitHub Pages with a language switch.
- **Dependency upgrades**: imapflow 1.7.8 → 2.0.2 (TypeScript rewrite; upstream fixed IDLE not re-entering after a session ends on its own), react 19.3.0 (react-dom in sync), lucide-react 1.45.0, @tanstack/react-virtual 3.14.12.

## Security and scope

- This release does not widen any external surface: no new outbound network endpoints were added, and mail content still stays on the machine by default; thread completion and retrieval run entirely against the local database.
- The update trust chain is unchanged: GitHub ZIP update assets continue to be verified with an Ed25519 manifest signature, and the installer embeds the public key.
- The local-first boundary is unchanged: account credentials stay on this device, and cloud models are used only when explicitly selected and consented to.

## Known limitations

- Windows x64 desktop only.
- Local retrieval does not ingest attachment bodies. Chinese is indexed per character, so questions whose wording differs greatly from the mail (for example 「报销」 versus 「费用申请」) rely on query expansion and hits may include noise.
- Availability, quotas, and output accuracy of cloud models and translation services depend on the chosen service; machine translation is only a reading aid.
