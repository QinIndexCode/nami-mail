# Nami Mail 0.2.3

[简体中文](v0.2.3.zh-CN.md) | [English](v0.2.3.en.md)

此说明为 Nami Mail `0.2.3` 准备的 GitHub Release 正文。它承接 `v0.2.0`、`v0.2.1` 和 `v0.2.2` 未公开源码标签中的用户功能与发布修复；这些 tag 都没有可下载的公开 GitHub Release 或更新资源，不能作为安装或自动更新来源。

## 下载

当 `v0.2.3` 发布为正式 GitHub Release 后，请只下载该 Release 页面列出的 Windows `.exe` 安装程序。版本化 ZIP、JSON 清单、`latest.yml` 和 `.blockmap` 是发行与应用内更新使用的资源，不是手动安装包。

## 本次更新

- 新增实验性的 NamiMail Agent 工作区：可在应用内配置 OpenAI-compatible 或 Ollama Provider，选择可访问账户范围，并从带来源引用的结果回到原邮件。
- 当前 Agent 工具仅可读取账户、文件夹、邮件、线程和附件元数据，以及创建、编辑或删除草稿。它不会直接归档、移动、标记、转发或发送邮件。
- 当前 Agent 检索使用本地加密页面上的词法匹配和范围过滤；未提供生产语义/embedding 索引，也不会从附件正文创建可检索页面。
- Provider 设置可从 Agent 和设置界面进入。云端 Provider 需要单独开启邮件内容使用范围；本地 Ollama Provider 保持本地处理边界。
- 改进左侧导航：全部账户、发送状态和系统文件夹使用不同的语义图标；账户选中、悬停和键盘焦点状态更清晰，不使用左侧强调条；在空间受限时账户与文件夹可独立滚动。
- 设置中的主题下拉框在按 `Esc` 时仅关闭列表，不再误关整个设置窗口。
- 保留实验性的主动邮件翻译功能。翻译只在用户选择后处理当前邮件正文，且机器翻译可能不准确。
- 强化 Windows 打包、安装器和桌面启动 smoke 的分层诊断。安装器 smoke 的临时已安装应用验证现在使用受控、项目拥有的隔离位置，并在成功后清理，避免系统临时目录环境差异掩盖实际失败。

## 安全与使用边界

- 外部 `namimail` CLI、MCP stdio、配对 Broker 和任何直接访问本地数据库的外部 Agent 接口均不可用，并会失败关闭。
- 邮件、附件名称、模型输出和引用都是不可信数据。Agent 只在用户选择的账户范围内读取上下文；高风险邮件操作仍由主邮件界面完成。
- 当前 Windows 安装程序未配置 Authenticode 签名。Windows SmartScreen 可能显示未知发布者提示；请核对仓库、tag 与安装程序名称，不要绕过系统安全检查。Ed25519 更新清单只用于应用内更新完整性验证，不能替代 Windows 的发布者信任提示。

## 自动更新状态

`0.2.3` 使用版本化 ZIP 与 JSON 清单绑定更新文件的版本、名称、大小和 SHA-512；配置 Ed25519 信任根时还会验证清单签名。发现更新不会自动下载或重启。

从已安装的 `0.1.2` 通过公开 GitHub Release 升级到 `0.2.3` 的真实线上验收尚未在本说明中声明为完成。只有在正式发布后完成该验收并保留可复查证据，后续版本说明才可表述为线上自动更新已验证。

## 已知限制

- 当前仅提供 Windows x64 安装程序。
- NamiMail Agent 是实验性嵌入式功能；外部 CLI/MCP 不可配置或启动，附件正文摄取、语义检索和邮件状态/发送工具尚未交付。
- 云端模型与翻译服务的可用性、配额和输出准确性取决于所选服务。只应在理解其隐私与保留政策后主动启用。
