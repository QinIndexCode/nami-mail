## 简体中文

### 下载与升级说明

**重要：仅针对 0.4.3 与 0.5.0 现有用户**
由于 `0.4.3` 与 `0.5.0` 内部运行的旧版更新器存在后台进程启动缺陷，无法直接在应用内完成自动升级。已安装 `0.4.3` 或 `0.5.0` 的用户请直接下载本页面列出的 `Nami-Mail-Setup-0.5.1.exe` 手动运行覆盖安装。
- 手动覆盖安装会**完全保留**现有全部本地数据与账户配置；
- 安装 `0.5.1` 之后，后续所有版本在应用内的自动检测、下载与“重启并更新”将全面恢复正常。

请只下载本 Release 页面列出的 Windows `.exe` 安装程序。版本化 ZIP、JSON 更新清单、`latest.yml` 和 `.blockmap` 是发行与应用内更新使用的资源，不是手动安装包，不应自行解压或运行。

### 主要变化

- **修复 Windows 重启更新后台进程退出缺陷（Node.js Issue #51018）**：重构后台更新进程拉起机制，改用 `cmd.exe /d /s /c start "" powershell.exe -WindowStyle Hidden` 在完全独立的新控制台会话中启动更新器，解决原 `spawn(..., { detached: true })` 导致 ConHost 宿主崩溃使更新器静默退出的严重问题。
- **补齐 NSIS 原地静默升级 `--updated` 标识**：更新器执行安装器时传递 `@('/S', '--updated')`，严格对齐 `installer.nsh` 静默升级逻辑，杜绝误触发运行确认弹窗并防止自定义安装路径被重置。
- **修复重启后工作目录漂移**：更新完成后自启动新版应用时显式传入安装目录为 `-WorkingDirectory`，防止工作目录漂移为 `C:\Windows\System32`。
- **增加更新失败缓存熔断与死循环保护**：当更新未成功改变版本时，主动清除损坏的更新缓存，杜绝重复弹出“重启并更新”。

### 更新与签名状态

- 本版本使用 **Ed25519 清单签名**作为更新信任根；**未进行 Authenticode 签名**，因此 Windows SmartScreen 可能显示"未知发布者"警告。请勿绕过 Windows 安全警告，只从本 Release 页面获取安装程序。
- 就地升级会保留现有本地数据；不会仅因本次更新而要求重新登录或重新授权账户。

### 已知问题与限制

- **Outlook / Hotmail 账户在默认安装下暂无法直接登录（跟踪 Issue #120）**：微软已关闭密码认证强制采用 OAuth2，由于官方构建尚未内置 Azure OAuth Client ID，当前微软登录暂不可用；可在 `%APPDATA%\Nami Mail\nami-mail.env` 配置 `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` 环境变量临时使用。
- 仅提供 Windows x64 桌面版。
- 本地检索不摄取附件正文；中文按单字切分。
- 云端模型与翻译服务可用性取决于所选第三方服务提供商。

## English

### Download & Upgrade Notice

**Important for 0.4.3 & 0.5.0 Users:**
Because the updater helper bundled within running `0.4.3` and `0.5.0` installations contains the process detachment flaw, in-app automatic updates cannot succeed from within 0.4.3 or 0.5.0. Users currently running 0.4.3 or 0.5.0 must download `Nami-Mail-Setup-0.5.1.exe` from this Release page and run it manually once.
- Manual in-place installation completely preserves all existing local data and accounts;
- Once upgraded to `0.5.1`, in-app automatic background updates and "Restart and update" are fully restored for all subsequent versions.

Download only the Windows `.exe` installer listed on this release page. The versioned ZIP, JSON update manifest, `latest.yml`, and `.blockmap` are distribution and in-app update resources, not manual installers — do not extract or run them yourself.

### Highlights

- **Fixed Windows Background Updater Detachment & Silent Exit (Node.js Issue #51018)**: Re-engineered updater launcher via `cmd.exe /d /s /c start "" powershell.exe -WindowStyle Hidden` in an independent console session, completely resolving silent exit without installation.
- **Added NSIS In-Place Upgrade Arguments (`--updated`)**: Passes `@('/S', '--updated')` to prevent running-process dialog prompts and protect custom installation paths from being reset.
- **Fixed Working Directory Drift on Relaunch**: Explicitly passes `-WorkingDirectory` to prevent newly relaunched application from inheriting `System32` as its working directory.
- **Added Update Failure Cache Purge**: Automatically cleans corrupted update archives when an update fails to apply, breaking recursive update prompt loops.

### Update and Signing Status

- Uses **Ed25519 manifest signature** as update trust root; **no Authenticode signature**, so Windows SmartScreen may display an "unknown publisher" warning. Do not bypass Windows security warnings; obtain installers only from this Release page.
- In-place upgrades preserve existing local data; re-login or re-authentication is not required.

### Known Issues & Limitations

- **Outlook / Hotmail Accounts (Issue #120)**: Microsoft OAuth2 requirement; requires `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` in `%APPDATA%\Nami Mail\nami-mail.env` until officially bundled.
- Windows x64 desktop only.
- Local search does not index attachment bodies; Chinese text segmented per character.
- Cloud models and translation availability depend on third-party providers.
