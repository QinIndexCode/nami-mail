# Nami Mail 0.7.0

[简体中文](v0.7.0.zh-CN.md) | [English](v0.7.0.en.md)

Nami Mail 0.7.0 makes "your data, your control" actionable: **remote mail images are blocked by default** with per-message authorization, sender trust, and revocation; **password-encrypted application snapshots** restore through isolated validation; compose gains **Markdown with live preview**, and **BCC is carried separately end to end, from mailto to SMTP**; auto-reply and failed tasks become persistent work you can review, retry, and reconcile.

## Read before upgrading: this update cannot be downgraded

- **Database gate v4 → v5 (one-time)**: 0.7.0 raises the database schema to v5 (durable failed-item acknowledgement, recovery attempts, and the auto-reply work queue). **After upgrading to 0.7.0 and completing its first launch, 0.6.0 and earlier refuse to open that database — you cannot roll back to 0.6.0 or older.** If you want a safety net, back up the entire `%APPDATA%\Nami Mail` directory first (the data directory holds a key bound to the current Windows user; it is not portable across machines or users).
- **Existing data is preserved**: the schema upgrade deletes no mail, accounts, settings, or keys; in-place upgrades require no re-login or reconfiguration.
- **Restores are explicitly confirmed**: a snapshot is validated in isolation before it is used, and only takes effect on a restart you confirm; unfinished remote work is paused during restore so nothing writes to the wrong data.

## Download and upgrade guide

- **On 0.6.0: in-app updates work** — detect, download, and "restart and update" to `0.7.0` inside the app.
- **On 0.5.0 or earlier**: those builds bundle the old broken updater and cannot update in-app; install `0.6.0` manually first, or install `0.7.0` directly.
- Download only the Windows `.exe` installer listed on the Release page. The versioned ZIP, JSON update manifest, `latest.yml`, and `.blockmap` are distribution and in-app update resources, not manual installers.

## Update and signing status

- Code gates: `verify-release-notes`, `sync:version:check`, `docs:claims:check`, and `docs:release-review` (BLOCK/EDIT at 0), plus typecheck / lint / all workspace tests / build, all pass; installer assets and signature status are as listed on this Release page.
- The `0.7.0` Windows installer keeps the **Ed25519 manifest signature** as its update trust root; it is not Authenticode-signed, so Windows SmartScreen may show an "unknown publisher" warning. Do not bypass Windows security warnings; obtain installers only from this Release page.
- **Real public-network upgrade acceptance from the previous version: pending verification** (run the documented 0.6.0 → 0.7.0 real-machine upgrade after release; until then this version makes no "verified automatic upgrade" claim).

## What's new

- **Data and privacy**: password-encrypted application snapshots you can export and restore on another machine; each restore is validated in an isolated directory and only activates on a confirmed restart, with the data key protected for portability; unfinished remote work is paused during a restore so old tasks cannot write to new data.
- **Remote images blocked by default**: opening a message no longer fetches third-party images. You can load them for one message, trust that sender, or revoke the trust at any time; authorization is re-checked on the server, and the notice and its actions are aligned.
- **Markdown compose with live preview**: GFM headings, lists, quotes, code, tables, and links, with a formatting toolbar and shortcuts; switch between edit and preview in the windowed composer, or write with a live side-by-side split when maximized. Sending inlines the formatting and compiles a standard `multipart/alternative` message that Gmail, Outlook, and Apple Mail render without plugins. Recipient fields suggest contacts and templates, and the contact list can start a message in one click.
- **BCC carried separately end to end**: mailto, compose, drafts, Agent confirmation, encrypted requests, and SMTP keep BCC as its own group. Partially rejected recipients stay visible; retrying a draft selects only the rejected addresses and keeps To/CC/BCC intact.
- **Failed tasks you can review, retry, and reconcile**: review failed items one by one, reapply them under your current identity, and acknowledge them durably. Send retries recover the body, threading, and available attachments, and partially rejected attachments keep the existing 24-hour staging window. Auto-reply now runs on a durable candidate queue reconciled against outbound results, fixing "queued means sent" and batches larger than 40 being dropped; unknown deliveries are never re-sent automatically.
- **More control over the assistant**: model providers now carry a connection, models, and explicit roles (chat / decision), including the TypeSafe System One (Jev) decision model and a decision threshold. Settings gains an Agent Tools page that lists all 33 built-in tools by domain with read/write tags, a banner that mirrors the current execution level, and a dedicated external MCP tab.
- **Calendar and mail details**: ICS time zones and invalid dates are handled correctly; the calendar pages fully by cursor, reminders query their own recent range, and local events keep their identity across export and import. Messages with ICS attachments are no longer downloaded twice, and thread merges keep already-loaded bodies.
- **Interface and accessibility**: Windows window controls become the standard caption band (flush right, full height, seamless, red close hover); the concentric-radius system is aligned on tokens; settings and compose baseline misalignments, wrong jump targets, and grouping semantics are fixed. AI polish maps timeouts, offline, auth, rate limits, and missing authorization to actionable localized messages while preserving the Markdown or plain-text writing mode.
- **Install experience**: the installer launch chain no longer flashes a console window, and the helper script ships with a UTF-8 BOM so Windows PowerShell 5.1 does not misread it as ANSI on non-English systems.

## Security and scope

- Local-first remains unchanged: backups, image authorization, and the task layer all run on the device with no central service;
- Cloud models still need explicit mail-content consent before they can search within that scope; external CLI/MCP keeps its read-only / send-confirmed / full-access tiers with confirmations that cannot be bypassed, and the externally visible tool surface equals the 16 tools the contract declares;
- The update trust root is unchanged: GitHub update assets continue to use Ed25519 manifest signature verification.

## Known issues and limitations

- **Outlook / Hotmail accounts cannot sign in on a default install (tracking Issue #120)**: Microsoft has disabled password authentication in favor of OAuth2 and the official build does not yet bundle an Azure OAuth client ID; set `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` in `%APPDATA%\Nami Mail\nami-mail.env` as a temporary workaround.
- **Remote images and open tracking**: images are blocked by default, but once you trust a sender, their unique image URL can still be used to observe opens; revoke that sender's trust if you do not want this.
- **Attachment preview boundaries**: legacy Office and HEIC/TIFF/PSD are not decoded (a download card explains why); PDF/scan rendering needs human visual acceptance.
- Windows x64 desktop only.
- Local search does not index attachment bodies; Chinese text is segmented per character.
- Cloud model and translation availability depends on the chosen third-party providers.
