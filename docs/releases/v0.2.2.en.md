# Nami Mail 0.2.2

[Chinese](v0.2.2.md) | [English](v0.2.2.en.md)

This is the prepared GitHub Release body for Nami Mail `0.2.2`. It carries user-facing work from the `v0.2.0` and `v0.2.1` source tags into one prepared release. Neither earlier tag has a public GitHub Release, downloadable installer, or update assets.

## Download

After `v0.2.2` is published as a stable GitHub Release, download only the Windows `.exe` installer listed on that Release page. Versioned ZIPs, JSON manifests, `latest.yml`, and `.blockmap` are release and in-app update resources, not manual installers.

## What's Changed

- Added the experimental NamiMail Agent workspace. Configure an OpenAI-compatible or Ollama provider in the app, choose the accessible account scope, and return from cited results to the original message.
- Current Agent tools can only read accounts, folders, messages, threads, and attachment metadata, plus create, edit, or delete drafts. They do not directly archive, move, flag, forward, or send mail.
- Current Agent retrieval uses lexical matching and scope filters over encrypted local pages. It does not ship a production semantic/embedding index or create searchable pages from attachment bodies.
- Provider settings are available from both Agent and Settings. Cloud providers require a separate enablement for mail-content use; local Ollama providers retain a local-processing boundary.
- Refined the left navigation: All accounts, sending status, and system folders use distinct semantic icons; account selected, hover, and keyboard-focus states are clearer without a left-side accent strip; account and folder lists scroll independently when space is constrained.
- A themed select in Settings now closes only its list when you press `Esc`; it no longer closes the entire Settings dialog.
- Retained experimental, user-triggered message translation. Translation processes the open message body only after you choose it, and machine translation can be inaccurate.
- Strengthened the layered Windows package, installer, and desktop-startup smoke diagnostics so a cold-start failure retains actionable error information.

## Security and Usage Boundaries

- External `namimail` CLI, MCP stdio, pairing Broker, and any external Agent route that directly accesses the local database are unavailable and fail closed.
- Mail, attachment names, model output, and citations are untrusted data. Agent reads context only inside the account scope you select; high-risk mail actions remain in the primary mail UI.
- The current Windows installer is not configured with an Authenticode signature. Windows SmartScreen may show an unknown-publisher warning; verify the repository, tag, and installer name instead of bypassing a system security check. The Ed25519 update manifest protects in-app update integrity only and does not replace Windows publisher trust.

## Automatic Update Status

`0.2.2` uses a versioned ZIP and JSON manifest to bind update version, name, size, and SHA-512. When an Ed25519 trust root is configured, it also verifies the manifest signature. Discovering an update never downloads or restarts automatically.

This note does not claim that real public-GitHub-Release upgrade acceptance from an installed `0.1.2` to `0.2.2` is complete. Only a later note may describe online automatic updates as verified after publication, successful acceptance, and retention of reviewable evidence.

## Known Limitations

- This version provides a Windows x64 installer only.
- NamiMail Agent is an experimental embedded feature. External CLI/MCP cannot be configured or started, and attachment-body ingestion, semantic retrieval, and mail-state/send tools have not shipped.
- Cloud-model and translation-service availability, quotas, and output accuracy depend on the chosen service. Enable them only after reviewing their privacy and retention policies.
