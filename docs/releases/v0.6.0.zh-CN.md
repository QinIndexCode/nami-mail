# Nami Mail 0.6.0

[简体中文](v0.6.0.zh-CN.md) | [English](v0.6.0.en.md)

Nami Mail 0.6.0 是一个里程碑版本：邮件数据库升级为**整库加密**，批量操作与发信重构为**可持久化的任务层**，附件获得**13 种格式的在线预览**，外部 CLI/MCP 的权限失败开始**自带解决路径**。这也是更新器修复（0.5.1）之后**第一次真实的应用内自动升级**。

## 升级前必读：本次升级不可降级

- **数据库格式变更**：0.6.0 把 SQLite 驱动切换为加密构建（ChaCha20-Poly1305 整库加密），并把数据库结构从 v2 迁移到 v4。**升级到 0.6.0 并完成首次启动后，无法降级回 0.5.1 或更早版本**——旧版本读不懂新的加密库。升级前如需保险，请整目录备份 `%APPDATA%\Nami Mail`（数据目录包含与当前 Windows 用户绑定的密钥，换机或换用户无法直接使用）。
- **首次启动的加密转换**：第一次启动 0.6.0 时，应用会把现有明文库升级为加密库（校验通过后原子换位）。转换过程中的意外断电/退出有多重恢复路径：加密副本校验通过即采纳、不可读时隔离保留（`.unreadable`）并告警、主库完好时清理重来——任何一条路径都不会静默丢失数据后当作空库新建。
- **就地升级保留一切**：邮件、账户、设置与加密密钥在升级后完整保留，不需要重新登录或重新配置。

## 下载与升级指引

- **0.5.1 用户：应用内升级已恢复**：从 `0.5.1` 起可直接在应用内检测、下载并"重启并更新"到 `0.6.0`。0.5.1 修复的更新器缺陷在本版本的更新路径上继续修复加固（包括数据目录路径含 `&` 等特殊字符导致更新助手无法启动的问题）。
- **0.4.3 与 0.5.0 用户**：这两个版本内置的旧更新器无法应用内升级，请先从 Release 页面下载安装包手动覆盖到 `0.5.1`（或直接手动安装 `0.6.0`）。
- 请只使用匹配 GitHub Release 页面列出的 Windows `.exe` 安装程序。版本化 ZIP、JSON 更新清单、`latest.yml` 和 `.blockmap` 用于发行与应用内更新，不是手动安装包。

## 更新与签名状态

- 代码门禁：CI 全量验证通过（typecheck / lint / 全部工作区测试 / e2e / 真实链路 e2e / desktop smoke / 生产依赖审计）；安装包资源与签名状态以本 Release 页面实际列出的资产为准。
- `0.6.0` Windows 安装程序沿用 **Ed25519 清单签名**作为更新信任根；未进行 Authenticode 签名，Windows SmartScreen 可能显示"未知发布者"警告。请勿绕过 Windows 安全警告，只从本 Release 页面获取安装程序。
- 就地升级保留现有本地数据；不会要求重新登录或重新授权账户。

## 本次更新

- **整库静态加密**：邮件数据库、图片缓存与敏感文件在本机静态加密（AES-256-GCM/ChaCha20-Poly1305 级别），主密钥由 Windows DPAPI 按当前用户保护。拿到数据库或缓存目录副本不再能直接读出邮件正文、主题或账户凭据。
- **统一任务层**：批量移动、标记、归档、撤销、发信与稍后提醒统一为可持久化任务——点击即生效、重启不丢、撤销跟随逆向任务到结算；服务商重建邮箱（UIDVALIDITY 变化）后，旧任务不会再写到另一封邮件上。
- **发信立即返回**：点发送后界面立即响应（202 + 本地乐观 Sent 行），SMTP 投递交给后台任务；同步抓回服务商 Sent 副本时按稳定标识认领，不再重复插入。
- **附件在线预览（13 种）**：PDF（严格模式）、图片、音视频、文本/代码、Markdown、Word/Excel/PPT、压缩包就地可读；预览走"取数 → 解码 → 文档 → 渲染"四层流水线，每个格式有明确的预算与失败说明，恶意文件最多显示为不可预览而不会执行；邮件正文远程图片与头像改走同源代理，浏览器不再直连第三方。
- **外部 CLI / MCP 更可用**：权限失败现在自带可行动的解决路径（去哪里开档位、如何重新配对、确认弹窗不可用时怎么办）；`namimail status` 一次看清调用方身份、档位与到期时间。
- **启动与故障韧性**：加密转换中断不会变空库、大库迁移分页进行、不可解密的消息会点名具体行、任务顺序跨重启保持、结算义务启动时幂等重放。

## 安全与范围

- 本地优先原则始终如一：新能力（任务层、预览、加密）全部在本机完成，无中央服务；
- 云端模型必须显式开启邮件内容授权后才可在授权范围内检索；外部 CLI/MCP 维持 read-only / send-confirmed / full-access 三档，确认不可绕过；
- 更新信任根保持不变：GitHub 更新资产继续使用 Ed25519 清单签名校验。

## 已知问题与限制

- **Outlook / Hotmail 账户在默认安装下暂无法直接登录（跟踪 Issue #120）**：微软已关闭密码认证强制采用 OAuth2，官方构建尚未内置 Azure OAuth Client ID；可在 `%APPDATA%\Nami Mail\nami-mail.env` 配置 `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` 环境变量临时使用。
- **远程图片与开信追踪**：远程图片经本地代理加载（渲染进程不直连），但发件人仍可通过唯一图片 URL 观察打开行为；"默认拦截 / 单封授权 / 按发件人放行"待产品决策。
- **附件预览边界**：旧版 Office 与 HEIC/TIFF/PSD 不解码（给出可下载说明）；PDF/扫描件的显示效果需真机目视验收；详见文档"已知限制"第 13 条。
- **平台支持**：当前仅提供 Windows x64 桌面版。
- **搜索与检索**：本地检索不摄取附件正文；中文按单字切分。
- **第三方服务**：云端模型与翻译服务可用性取决于所选第三方服务提供商。
