# Nami Mail 0.3.0

[Chinese](v0.3.0.zh-CN.md) | [English](v0.3.0.en.md)

Nami Mail 0.3.0 introduces the first formal External Mail v1 local interface. It is for the Windows desktop app, paired local scripts, and MCP clients, while preserving local-first, default-deny, read-only boundaries.

## Download

Use only the Windows `.exe` installer listed on the matching GitHub Release page. Versioned ZIPs, JSON update manifests, `latest.yml`, and `.blockmap` are for release and in-app updates, not manual installers.

## Update and Signing Status

- Pre-release acceptance: the `0.3.0-m3acc` build passed all local smoke suites (desktop / package / installer). The desktop smoke covers the desktop bridge, isolated data directory, and content security policy; the package smoke covers packaged artifacts and the installer; the installer smoke covers silent install, CLI path registration, same/lower-version upgrade policy, and MCP smoke, with `tools/list` returning fifteen External Mail v1 tools after install.
- Public-network auto-update acceptance from `0.2.3` to `0.3.0` is still pending. This release does not claim the online upgrade path has been accepted until isolated verification is complete.
- The `0.3.0` Windows installer is not Authenticode-signed. Windows SmartScreen may show an unknown-publisher warning. Do not bypass a Windows security warning; obtain the installer only from this Release page.
- The in-place install preserves existing local data. No sign-in or re-authorization is required solely because of this update.

## What's Changed

- Added the installer-provided `namimail` PATH shim and direct `"Nami Mail.exe" --cli <args>` invocation.
- Added `namimail service start`, `status`, and `doctor` to explicitly start or inspect the local AgentHost. Ordinary reads and MCP stdio never start a host implicitly.
- Added desktop-visible `namimail pair --profile <name>` and `namimail revoke --profile <name>` flows. First pairing fixes the current account-ID snapshot, and an account added later never enters an old profile automatically.
- Added local MCP stdio access via `namimail mcp start --profile <name>`. It supports MCP protocols `2025-03-26` and `2025-06-18` (the server echoes the client's requested version) and publishes fifteen External Mail v1 tools from `tools/list` (eight read-only plus seven bounded writes). MCP client configuration must use a `cmd /c` host; see [MCP configuration](https://github.com/QinIndexCode/nami-mail/blob/main/docs/mcp/configuration.en.md).
- External Mail v1 reads accounts, folders, message lists, message detail (single and batch), threads, and attachment metadata, and provides bounded writes: draft create/update/delete, message move (archive/trash), seen/flagged state, send, and reply. Successful data is validated by versioned strict schemas; mail bodies are bounded plain text and attachments are never exported as files.
- Added stable success/failure envelopes, error codes, account scope, and update-drain recovery semantics for scripts and MCP. The GUI main instance actively rebuilds the named-pipe Broker after an abnormal exit, avoiding a false "running but unavailable" state.
- Retained experimental local NLLB-200 translation. It remains prepared and triggered explicitly in the desktop reader and is not a CLI/MCP tool.
- Added a local mail template library: manage frequently used subjects and bodies in Settings and insert one into a compose or reply with a single click.
- Added inline attachment preview: PDFs and images render in a read-only viewer; DOCX / PPTX / XLSX and common text files get a read-only text preview without exporting the original file.

## Security and Scope

- CLI/MCP reach the running host only through a paired Windows named-pipe Broker restricted to the current user SID.
- It cannot reuse a Fastify token, HTTP/TCP, SQLite, a file URI, mail credentials, or a database path as an integration channel.
- Every profile has an independent protected identity, signature, and monotonic counter. Revocation, identity mismatch, and replay are rejected.
- External v1 writes are limited to bounded draft and send operations: draft create/update/delete, move (archive/trash), seen/flagged state, send, and reply. Forwarding, account configuration changes, RAG, chat, and attachment export remain unsupported.

## Known Limits

- Windows x64 desktop is the only supported platform.
- MCP v1 exposes no Resources, streaming mail events, or hidden tools. A client should call `tools/list` again for every new session.
- Cloud-model and translation-service availability, quotas, and output accuracy depend on the selected service. Machine translation is reading assistance only.
