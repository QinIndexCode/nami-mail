# Nami Mail 0.2.0 (unpublished source tag)

[Chinese](v0.2.0.md) | [English](v0.2.0.en.md)

`v0.2.0` did not complete release validation and has no public GitHub Release or downloadable assets. It must not be used for manual installation or automatic updates. This note remains only as a record of the source tag; its user-visible changes continue through the unpublished [v0.2.1](v0.2.1.en.md) and [v0.2.2](v0.2.2.en.md) source tags and are carried forward by the prepared [v0.2.3](v0.2.3.en.md) release.

## Publication Status

This tag has no Release page, Windows installer, versioned ZIP, JSON manifest, `latest.yml`, or `.blockmap` asset. Download a Windows `.exe` installer only from the Release page of a published version.

## What's Changed

- Added the experimental NamiMail Agent workspace. Configure an OpenAI-compatible or Ollama provider in the app, choose the accessible account scope, and return from cited results to the original message.
- Current Agent tools can only read accounts, folders, messages, threads, and attachment metadata, plus create, edit, or delete drafts. They do not directly archive, move, flag, forward, or send mail.
- Current Agent retrieval uses lexical matching and scope filters over encrypted local pages. It does not ship a production semantic/embedding index or create searchable pages from attachment bodies.
- Provider settings are available from both Agent and Settings. Cloud providers require a separate enablement for mail-content use; local Ollama providers retain a local-processing boundary.
- Refined the left navigation: All accounts, sending status, and system folders use distinct semantic icons; account selected, hover, and keyboard-focus states are clearer without a left-side accent strip; account and folder lists scroll independently when space is constrained.
- Retained experimental, user-triggered message translation. Translation processes the open message body only after you choose it, and machine translation can be inaccurate.

## Security and Usage Boundaries

- External `namimail` CLI, MCP stdio, pairing Broker, and any external Agent route that directly accesses the local database are unavailable in the code represented by this source tag and fail closed.
- Mail, attachment names, model output, and citations are untrusted data. Agent reads context only inside the account scope you select; high-risk mail actions remain in the primary mail UI.
- Before installation, verify the repository, tag, Windows `.exe` installer name, and publisher information on the Release page. Do not bypass a Windows trust warning.

## Automatic Update Design (not published)

Subsequent public Releases use a versioned ZIP and JSON manifest to bind update version, name, size, and SHA-512. When an Ed25519 trust root is configured, they also verify the manifest signature. Discovering an update never downloads or restarts automatically.

This tag cannot be an update target. Real public-GitHub-Release upgrade acceptance from an installed `0.1.2` to a later published version, currently the prepared `0.2.3`, must be completed after publication with reviewable evidence.

## Known Limitations

- A later published version is currently planned to provide a Windows x64 installer only.
- NamiMail Agent is an experimental embedded capability in this source tag. External CLI/MCP cannot be configured or started, and attachment-body ingestion, semantic retrieval, and mail-state/send tools have not shipped.
- Cloud-model and translation-service availability, quotas, and output accuracy depend on the chosen service. Enable them only after reviewing their privacy and retention policies.

For more help, see [Windows installation and updates](https://github.com/QinIndexCode/nami-mail/blob/main/docs/INSTALLING.en.md), [NamiMail Agent architecture and boundaries](https://github.com/QinIndexCode/nami-mail/blob/main/docs/agent/architecture.en.md), [mail RAG](https://github.com/QinIndexCode/nami-mail/blob/main/docs/rag/architecture.en.md), and [privacy and local data](https://github.com/QinIndexCode/nami-mail/blob/main/docs/PRIVACY.en.md).
