# Nami Mail 0.7.0

[简体中文](v0.7.0.zh-CN.md) | [English](v0.7.0.en.md)

Nami Mail 0.7.0 把“数据与隐私”落到可操作的层面：**远程邮件图片默认阻止**并可逐封授权、信任发件人及撤销，新增**口令加密的应用快照**与隔离校验的恢复流程；写信支持 **Markdown 与实时预览**，**密送从 mailto 到 SMTP 全链路独立贯通**；自动回复与失败任务改为可审阅、可重试、可对账的持久任务。

## 升级前必读：本次升级不可降级

- **数据库门禁 v4 → v5（一次性）**：0.7.0 把数据库结构升级到 v5（失败任务知悉、恢复尝试与自动回复工作队列等持久化数据）。**升级到 0.7.0 并完成首次启动后，0.6.0 及更早版本会拒绝打开该数据库，无法降级回 0.6.0 或更早版本**。升级前如需保险，请整目录备份 `%APPDATA%\Nami Mail`（数据目录包含与当前 Windows 用户绑定的密钥，换机或换用户无法直接使用）。
- **旧数据完整保留**：结构升级不删除任何邮件、账户、设置或密钥；就地升级后不需要重新登录或重新配置。
- **恢复流程是显式确认的**：应用快照在恢复前先在隔离环境校验，只有确认后重启才启用；恢复期间未决的远端操作会被暂停，先看清再继续。

## 下载与升级指引

- **0.6.0 用户：可直接应用内升级**——在应用内检测、下载并“重启并更新”到 `0.7.0`。
- **0.5.0 及更早版本**：内置的旧更新器无法应用内升级，请先手动安装 `0.6.0`，或直接从本页面安装 `0.7.0`。
- 请只使用匹配 GitHub Release 页面列出的 Windows `.exe` 安装程序。版本化 ZIP、JSON 更新清单、`latest.yml` 和 `.blockmap` 用于发行与应用内更新，不是手动安装包。

## 更新与签名状态

- 代码门禁：`verify-release-notes`、`sync:version:check`、`docs:claims:check`、`docs:release-review`（BLOCK/EDIT 为 0），以及 typecheck / lint / 全部工作区测试 / build 全部通过；安装包资源与签名状态以本 Release 页面实际列出的资产为准。
- `0.7.0` Windows 安装程序沿用 **Ed25519 清单签名**作为更新信任根；未进行 Authenticode 签名，Windows SmartScreen 可能显示“未知发布者”警告。请勿绕过 Windows 安全警告，只从本 Release 页面获取安装程序。
- **真实旧版到新版的公开网络更新验收：待验证**（发布后按发布指南完成 0.6.0 → 0.7.0 的真机更新验收；完成前本版本不作“已验证可自动升级”的承诺）。

## 本次更新

- **数据与隐私**：新增口令加密的应用快照——可导出、可换机恢复；恢复前在隔离目录校验，确认后重启才启用，并保护换机所需的数据密钥；恢复期间暂停未决的远端操作，避免旧任务写到新数据上。
- **远程图片默认阻止**：打开邮件不再自动请求第三方图片；可按单封加载、信任该发件人，也可随时撤销信任。授权在服务端再次校验，界面提示与操作按钮同步对齐。
- **写信支持 Markdown 与邮件富文本实时预览**：支持 GFM 标题、列表、引用、代码、表格与链接，提供快捷格式化工具栏与快捷键；普通窗口可“编辑/预览”切换，最大化窗口为左右实时分屏；发送时自动内联排版并编译为标准 `multipart/alternative`，主流邮件客户端免插件可读。收件人输入框支持联系人与模板快速搜索，联系人列表可一键写信。
- **密送（BCC）全链路独立贯通**：mailto、撰写、草稿、Agent 确认、加密请求与 SMTP 全程保留密送分组；部分收件人被拒收时会持久显示，重试草稿只选择被拒地址并保留 To/CC/BCC 可见性。
- **失败任务可审阅、可重试、可对账**：失败任务支持逐项审阅、按当前身份重新操作与持久知悉；发送重试恢复正文、线程与可用附件，部分拒收附件沿用 24 小时暂存窗口；自动回复改为持久候选队列并对账出站结果，修复“排队即报成功”和单批超过 40 封被丢弃，未知投递不会自动重发。
- **智能体更可控**：模型提供商支持连接、模型与显式角色（chat / decision），接入 TypeSafe System One（Jev）纯判定模型与判定阈值；设置新增「智能体工具」页，按领域列出全部 33 个内置工具并标注只读/写入，页面横幅实时反映当前执行权限，外部 MCP 服务在同一页面统一管理。
- **日历与邮件细节**：修复 ICS 时区与非法日期处理，日历按游标完整加载、提醒独立按近期范围查询，本地日程导出再导入保留身份；含 ICS 附件的邮件不再重复下载，同一会话合并时保留已加载的正文。
- **界面与可访问性**：Windows 窗口控件改为系统标准标题栏按钮（贴右缘、满高、无缝、红色关闭悬停）；全局同心圆角体系按 token 对齐；修复设置与写信界面的基线错位、错误跳转与分组语义；AI 润色把模型超时、离线、认证失败、限流与未授权映射为可行动的本地化提示，并在润色前后保持 Markdown / 纯文本书写模式。
- **安装体验**：安装器启动链路不再闪现控制台窗口，助手脚本携带 UTF-8 BOM，避免中文等非英文系统上 Windows PowerShell 5.1 按 ANSI 解析失败。

## 安全与范围

- 本地优先原则始终如一：新增的备份、图片授权与任务能力全部在本机完成，无中央服务；
- 云端模型必须显式开启邮件内容授权后才可在授权范围内检索；外部 CLI/MCP 维持 read-only / send-confirmed / full-access 三档，确认不可绕过，外部可见工具面等于契约声明的 16 个；
- 更新信任根保持不变：GitHub 更新资产继续使用 Ed25519 清单签名校验。

## 已知问题与限制

- **Outlook / Hotmail 账户在默认安装下暂无法直接登录（跟踪 Issue #120）**：微软已关闭密码认证强制采用 OAuth2，官方构建尚未内置 Azure OAuth Client ID；可在 `%APPDATA%\Nami Mail\nami-mail.env` 配置 `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` 环境变量临时使用。
- **远程图片与开信追踪**：远程图片默认阻止，但你对某位发件人授权后，其唯一图片 URL 仍可用于观察打开行为；不需要时请撤销该发件人的信任。
- **附件预览边界**：旧版 Office 与 HEIC/TIFF/PSD 不解码（给出可下载说明）；PDF/扫描件的显示效果需真机目视验收。
- **平台支持**：当前仅提供 Windows x64 桌面版。
- **搜索与检索**：本地检索不摄取附件正文；中文按单字切分。
- **第三方服务**：云端模型与翻译服务可用性取决于所选第三方服务提供商。
