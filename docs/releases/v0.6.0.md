## 简体中文

### 升级前必读

**本次升级不可降级**：0.6.0 将邮件数据库升级为整库加密（ChaCha20-Poly1305）并把结构迁移到 v4，升级并完成首次启动后无法回退到 0.5.1 或更早版本。首次启动时的加密转换有多重恢复路径（校验采纳 / 不可读隔离 / 主库完好重来），不会静默丢数据；如需保险请先整目录备份 `%APPDATA%\Nami Mail`。就地升级保留全部邮件、账户、设置与密钥。

**0.5.1 用户可直接应用内升级**（更新器修复后的首次真实自动升级）；**0.4.3 / 0.5.0 用户**内置旧更新器无法升级，请手动安装 0.5.1 或直接安装 0.6.0。

请只下载本 Release 页面列出的 Windows `.exe` 安装程序；版本化 ZIP、JSON 清单、`latest.yml` 与 `.blockmap` 是发行和更新资源，不是手动安装包。

### 主要变化

- **整库静态加密**：数据库与敏感缓存本机加密，主密钥由 Windows DPAPI 按用户保护；拿到文件副本不再能直接读出邮件内容。
- **统一任务层**：批量移动/标记/归档/撤销/发信/稍后提醒成为持久化任务——点击即生效、重启不丢、撤销跟随逆向任务；服务商重建邮箱后旧任务不会写错邮件。
- **发信立即返回**：发送即刻响应（202 + 本地乐观 Sent 行），投递交后台任务，Sent 副本按稳定标识认领不重复。
- **附件在线预览（13 种）**：PDF/图片/音视频/文本/Markdown/Office/压缩包就地可读，四层流水线带预算与失败说明；远程图片与头像改走同源代理。
- **外部 CLI/MCP 权限失败自带解决路径**：指引到设置档位、重新配对或确认流程；`namimail status` 一次看清身份、档位与到期。
- **启动与故障韧性**：转换中断不变空库、迁移分页、坏数据点名、任务顺序跨重启、结算义务幂等重放。

### 更新与签名状态

- 沿用 **Ed25519 清单签名**作为更新信任根；**未进行 Authenticode 签名**，SmartScreen 可能显示"未知发布者"警告，请勿绕过，只从本 Release 页面获取安装程序。
- 就地升级保留现有本地数据；不会要求重新登录或重新授权账户。

### 已知问题与限制

- **Outlook / Hotmail 暂无法在默认安装下登录（Issue #120）**：需 OAuth2 Client ID；可在 `%APPDATA%\Nami Mail\nami-mail.env` 配置 `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` 临时使用。
- 远程图片经本地代理加载，但发件人仍可通过唯一 URL 观察打开行为（拦截策略待产品决策）。
- 附件预览不支持旧版 Office 与 HEIC/TIFF/PSD（给出可下载说明）；PDF/扫描件需真机目视验收。
- 仅提供 Windows x64 桌面版；本地检索不摄取附件正文，中文按单字切分；云端服务取决于第三方提供商。

## English

### Read before upgrading

**This update cannot be downgraded**: 0.6.0 upgrades the mail database to whole-file encryption (ChaCha20-Poly1305) and migrates the schema to v4; after upgrading and completing the first launch you cannot roll back to 0.5.1 or earlier. The first-launch conversion has multiple recovery paths (verified adoption / quarantine / clean restart) and never silently loses data; back up `%APPDATA%\Nami Mail` first if you want a safety net. In-place upgrades preserve all mail, accounts, settings, and keys.

**0.5.1 users can update in-app** (the first real automatic upgrade since the updater fix); **0.4.3 / 0.5.0 users** bundle the old broken updater and must install 0.5.1 or 0.6.0 manually.

Download only the Windows `.exe` installer listed on this Release page; the versioned ZIP, JSON manifest, `latest.yml`, and `.blockmap` are distribution and update resources, not manual installers.

### Highlights

- **Encryption at rest**: database and sensitive caches encrypted on disk, master key protected by Windows DPAPI per user; a file copy no longer reveals mail content.
- **Unified task layer**: batch move/flag/archive/undo/send/snooze become persistent tasks — effective on click, restart-safe, undo follows the reverse task; old tasks stop writing to the wrong message after a provider mailbox rebuild.
- **Send returns immediately**: 202 + optimistic local Sent row, delivery in the background, Sent copies claimed by stable identifier without duplicates.
- **Attachment preview (13 kinds)**: PDF/images/audio/video/text/Markdown/Office/archives read in place on a four-stage pipeline with budgets and failure explanations; remote images and avatars go through a same-origin proxy.
- **External CLI/MCP failures explain their own fix**: guidance to the settings tier, re-pairing, or the confirmation flow; `namimail status` shows identity, tier, and expiry in one command.
- **Startup and failure resilience**: interrupted conversions never become empty databases, paged migrations, named bad rows, restart-safe task order, idempotent settlement replay.

### Update and Signing Status

- Keeps the **Ed25519 manifest signature** as the update trust root; **no Authenticode signature**, so SmartScreen may show an "unknown publisher" warning — do not bypass it, and obtain installers only from this Release page.
- In-place upgrades preserve existing local data; re-login or re-authorization is not required.

### Known Issues & Limitations

- **Outlook / Hotmail cannot sign in on a default install (Issue #120)**: requires an OAuth2 client ID; set `NAMI_MAIL_MICROSOFT_OAUTH_CLIENT_ID` in `%APPDATA%\Nami Mail\nami-mail.env` as a workaround.
- Remote images load through the local proxy, but a sender can still observe opens via a unique URL (blocking policy pending a product decision).
- Attachment preview does not decode legacy Office or HEIC/TIFF/PSD (a download card explains); PDF/scans need human visual acceptance.
- Windows x64 desktop only; local search does not index attachment bodies and segments Chinese per character; cloud services depend on third-party providers.
